01

The site tells Google its own address is a Vercel preview URL — with a double slash

BlockerTrivialArticles

Confirmed live on a real article: og:url and JSON-LD url both read https://sac-website.vercel.app//blog/2026/08/23/.... The real site is www.sociedadastronomia.com.

Fixdata/siteMetadata.js:12 → 'https://www.sociedadastronomia.com', no trailing slash. Add a Jest assertion that it never ends in /, and route every concatenation through one absUrl() helper so it cannot regress.

02

A second, fully indexable copy of the entire site is live at sac-website.vercel.app

BlockerSmallArticles

Both hosts serve byte-identical pages at 200 with robots: index, follow and no canonical. The only URL hints on the page point at the twin. Link equity splits across two hosts and Google picks the winner, which may not be the one you want.

Fix308 the preview host in next.config.js using redirects() with has: [{ type: 'host', value: 'sac-website.vercel.app' }], or set the production domain in the Vercel dashboard. A redirect beats noindex because it also transfers the existing links.

Claims that did not survive review

42 of 132 refuted

Each finding was handed to an independent agent instructed to refute it. These are the notable ones that failed, listed so nobody spends a sprint on them later.

Relative publisher.logo.url invalidates the Article rich result
Retired AMP-era requirement. Google dropped the publisher logo from Article guidance; it no longer gates the rich result.
Missing mainEntityOfPage weakens the Article schema
Not a required property and not used as a ranking or eligibility signal.
One headline exceeds Google's 110-character limit
Also an AMP-era rule, since removed from the spec.
Articles should use NewsArticle, not Article
Article is valid for news. The subtype confers no advantage without Google News enrolment.
Hero images under 1200px fail the schema image requirement
Threshold misattributed; it applies to a rich-result format this site is not eligible for anyway.
Skipping h2 and jumping h1 → h3 hurts rankings
Heading-weight folklore. Strict hierarchy is an accessibility concern, not a ranking factor. (Adding subheadings is still recommended above — for snippets and readers, not for hierarchy.)
Two h1 elements on one article page
Real, but multiple h1 has not been a ranking issue since HTML5 sectioning.
Missing WebSite schema with SearchAction
Google removed the sitelinks search box feature and its documentation.
site.webmanifest has empty names and 404 icon paths
Accurate, but Google Search does not parse the web app manifest. Worth fixing; not SEO.
The Pages-Router 404 declares lang="en"
Half fabricated — the App Router 404 does not. The surviving half targets a non-indexable surface.
16 articles render raw unoptimized <img> tags
The two code quotes were accurate but the causal chain joining them was wrong. The real image problem is #11 above.
The events page lacks Event schema
The page is deliberately disabled and contains no events. Nothing to mark up. Revisit if events return — see the strategy note below.

Where the real upside is

Content strategy

Grounded in the actual corpus. The organisation's one defensible advantage is being the local astronomical authority for Puerto Rico. 24 of 77 titles already carry that signal and they correlate with the strongest pages. The other 54 compete head-on with NASA and global wire copy, and lose.

1. Replace disposable event news with evergreen hubs

The corpus covers the same events every cycle — eclipses, Perseidas, visible launches, comets — and each post ranks for two weeks then dies. Build four hubs that get updated rather than replaced: Eclipses visibles desde Puerto Rico, Lluvias de meteoros: calendario para Puerto Rico, Lanzamientos visibles desde la Isla, Cometas visibles ahora. Every news post links up to its hub; the hub links down to the current event. That turns 40+ isolated items into four pages that accumulate authority year over year — and it solves the internal-linking problem at the same time.

2. Own "¿qué fue esa luz en el cielo?"

SAC is already the de facto bolide reporting body for the island, and these events produce enormous instantaneous local search spikes in colloquial Spanish. Your own copy shows it:

"Se vio enorme, mostrando una cola y un color verdoso", coincidieron varios observadores al reportar el avistamiento a la Sociedad de Astronomía del Caribe.

Build a permanent Reporta un bólido o avistamiento page with a report form, plus an annual roundup. Then title future posts the way people type: "¿Qué fue la luz verde en el cielo de Puerto Rico anoche?" rather than "Brillante meteoro avistado".

3. Rebuild the telescope guide as the commercial anchor

It is the one page with recurring purchase intent, it is already in the sitewide nav, and it is currently dated 2000 and buried on page 16. Fix the date, expand it, retitle toward the query ("Qué telescopio comprar: guía para principiantes en Puerto Rico"), and spin off satellites — telescopio para niños, binoculares para astronomía, dónde comprar en PR. Link every "cómo verlo" news post to it. Highest-yield single page on the site, currently the hardest to reach.

4. Standardize a local answer block on every viewing article

The articles that already win have a place name in the title: "Desde Isabela, PR: Espectacular foto del Cometa 220P / McNaught". Add three fixed subheadings to every observable-event post: ¿A qué hora se verá desde Puerto Rico? (with AST times), ¿Hacia dónde mirar?, ¿Necesito telescopio? This fixes the missing-subheadings finding, creates featured-snippet targets, and reinforces the geographic signal in one move.

5. Ship the observation guides as real pages

The three editions in S3 hold roughly 66 deep-sky objects with magnitudes, difficulty ratings, equipment notes and optimal observing times. That is first-party, structured, evergreen, locally-scoped data no wire service can duplicate — and today none of it reaches the server HTML. Per-edition URLs with per-object anchors turn it into the site's most durable ranking asset.
